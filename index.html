Private key → public key (toy elliptic curve)

Curve y² = x³ + 7 (mod 17), base point G = (1,5). Ethereum uses the same idea on secp256k1.

01 · Introduction

This project demonstrates how a private key generates a public key using elliptic curve scalar multiplication.

The public key is calculated as:

Q = kG

where k is the private key and G is the base point.

02 · Toy Curve Parameters

  • Base Point: G = (1, 5)

07 · Security Discussion

Computing the public key Q = kG from a private key k is easy.

Recovering k from the public key Q is based on the Elliptic Curve Discrete Logarithm Problem (ECDLP), which becomes computationally infeasible on large curves such as secp256k1.

Discussion

Meaningful for a cryptographic one-way function:

  • Easy forward, hard backward. Computing kB is fast, but recovering k is the ECDLP. This hardness is not a statistical property, so no table here can prove or disprove it.
  • Apparent uniformity. Over k = 1 … n−1 every point of the subgroup appears exactly once, so the outputs are uniform over the subgroup but not over all 17×17 coordinate pairs. In the toy curve many x values never occur, and bit 4 is almost always 0 because values are at most 16. Real systems encode points carefully for this reason.
  • No visible input/output correlation. A near-zero correlation is a useful sanity check, but it does not prove security. The scatter plot shows hidden structure: x(kB) = x((n−k)B), because (n−k)B = −kB.

Properties specifically associated with cryptographic hash functions:

  • Avalanche effect. Flipping one input bit should flip about half the output bits. Scalar multiplication is not designed for this: (k+1)B = kB + B, so neighbouring inputs give related outputs.
  • Collision and second-preimage resistance, fixed-size output for any input, pseudo-random output bits. These are hash design goals. The toy curve has none of them (outputs repeat with period n).
  • No algebraic structure. Elliptic-curve multiplication is homomorphic: (k1+k2)B = k1B + k2B. That structure is what makes public-key schemes and signatures possible, and it is exactly what a good hash must not have.

All numbers here come from a 17-element field, so they describe the toy curve, not secp256k1. At 256 bits, brute-force or statistical attacks on k are infeasible.
